Quickstart

Running in 60 seconds

No signup. No OpenAI key. BM25 retrieval works out of the box — embeddings are optional and pluggable (Ollama, vLLM, TEI, llama.cpp) when you want them.

# one command — daemon on :14800, MCP on :14801, console embedded
$ docker compose up -d
$ open http://127.0.0.1:14800/console   # one-time setup wizard
$ curl -sSL https://github.com/CueCrux/Crux/releases/latest/download/crux-linux-amd64 -o crux
$ chmod +x crux
$ CORECRUXD_AUTH_MODE=off CORECRUXD_DATA_DIR=./data ./crux
# releases are cosign-signed with SBOMs — see docs/verify-release.md
$ git clone https://github.com/CueCrux/Crux.git && cd Crux
$ cargo build --release          # Rust ≥ 1.88, protobuf-compiler
$ CORECRUXD_AUTH_MODE=off CORECRUXD_DATA_DIR=./data ./target/release/corecruxd
// .mcp.json — works with Claude Code, Claude Desktop, Cursor, any MCP client
{
  "crux": { "url": "http://127.0.0.1:14801/mcp" }
}

What you get

Three planes, one daemon

Memory that ages honestly

Facts carry confidence, provenance and a freshness horizon. A deterministic decay engine (volatile 24h · medium 35d · stable 365d) downranks stale claims instead of serving them as truth — reversible via memory_reverify. Scoped forget for GDPR Art. 17.

Retrieval on a token budget

token_budget is a required parameter, not a hope. BM25 + graph fusion returns metadata and token counts first, content only inside budget — 60–80% fewer tokens than naive top-K context stuffing. Dense lanes optional, never required.

Receipts, not vibes

Every write emits a CROWN receipt: Ed25519-signed, BLAKE3-chained, independently verifiable offline with corecruxctl verify-store. Tamper with one byte and the chain fails loudly. C2PA output attestation for EU AI Act Art. 50.

Three pillars, color-coded (green/cyan/amber) — the same colors thread through the charts, diagrams and console shots below, so the README teaches its own legend. Quantified benefit bullets per the uv pattern ("60–80% fewer tokens", "24h/35d/365d") rather than a feature laundry list. Receipts get the strongest verbs; it's the column neither competitor can copy quickly.

Identity

Passports — identity agents earn

API keys say something with this string called us. A passport says this agent, at this trust tier, with these grants, did this — and the receipts prove it. Identity isn't configured once; it's earned, write by verified write.

1

Bind

The session handshake binds every connection to a passport. There are no anonymous writes — unattributed calls get operator-tagged, never silently allowed.

2

Carry

Every tool call rides the passport. RCX mints short-lived capability tokens against it — scoped to tools, tenant and tier — so access expires instead of leaking.

3

Earn

Verified receipts accrue to the passport as reputation. Tiers climb the capability ladder and unlock more autonomy; a sponsor can vouch an agent up faster. Trust is a ledger, not a checkbox.

4

Answer

Any receipt, any time later, resolves back to the passport that produced it: who acted, at what tier, under which grants. That's the question auditors actually ask — pre-answered.

The passport card is real data shape — id format, tier, group, sponsor, receipts count, session TTL and the capability strings all come from the live daemon's boot surface, lightly redacted. CoreCrux + AMR

Frontier-grade recall. Zero custody.

That 91.2% LongMemEval (strict) isn't the bare daemon flexing — it's CoreCrux, the GPU retrieval substrate behind the paid tier. You can pay for frontier-model ingest and extraction over your corpus. You cannot pay us to hold your data — there is no such product.

1 · your store

Everything starts local

Facts, documents and sessions live in your /data — append-only, receipt-chained, portable. This never changes.

2 · frontier ingest (paid)

Enriched in flight

Frontier models extract entities, events, traits and summaries from your corpus — processed, never parked. Every hop carries a receipt.

3 · returned & deleted

Results come home

Enrichment lands back in your store. Process, return, delete — we hold nothing, before or after.

Local-first isn't a pricing tier — it's the architecture. The paid lane rents compute, not custody.

AMR — Adaptive Manifest Routing

Every query is different, so AMR reads the lane manifest and routes each one automatically — fusing the lanes that earn their tokens, skipping the ones that don't, learning from per-request outcomes. No knobs, no lane config, no prompt engineering. Automatic, and opt-in: it switches on with a subscription and stays off otherwise — like everything else in Crux.

Without a subscription

You still run the full local daemon: lexical lane, graph fusion, token budgets, receipts. That's not a demo — it's the same engine the paid lanes plug into. Upgrade when your corpus outgrows it, not because a feature gate told you to.

The RCX protocol

Every request resolves a principal: which agent, holding which passport, at which tier. The crux-router policy layer walks the capability ladder and allows or denies per tool — and the decision itself lands in the receipt, so "who could do what, when" is replayable forever.

Capability tokens

Access rides short-lived signed JWTs (rcx-capability-token) minted against a passport and scoped to tools, tenant and tier — not a god-key in an env var. Tokens verify offline with the same machinery as receipts. Lose one, it expires; mint another.

Tier columns mirror the daemon's existing local / BYOE / hosted split. Agent action tracing is gated behind CORECRUXD_OBSERVE (off by default — your traces are opt-in, like everything else).

EU AI Act

Compliance you can replay, not just claim

The Act asks for risk management, logging, transparency and human oversight. Most stacks will answer with PDFs. Crux answers with receipts — the compliance machinery is the same machinery everything else runs on, not a bolt-on audit module.

ART. 9 · RISK MANAGEMENT

Risk classes on every plan

Work items and plans declare low | medium | high risk. High-risk transitions demand a passport-attributed human gate before they run — and the gate itself becomes a signed fact.

ART. 10 · DATA GOVERNANCE

PII is born private

Private facts never leave the machine; reserved prefixes are private at ingest; observation capture redacts; reasoning is stored as references — never raw chain-of-thought.

ART. 12 · RECORD-KEEPING

Logging you can't forget to do

Every state mutation emits a signed CROWN receipt and a timeline row automatically. Retention: 90-day receipts, indefinite decision facts. The trail is hash-chained — gaps are detectable, not deniable.

ART. 13 · TRANSPARENCY

Every write has an author

Agent passports attribute every mutation. AI-authored commits and PRs carry agent attribution; end-user-facing output carries an AI-involvement notice.

ART. 14 · HUMAN OVERSIGHT

Gates that don't rubber-stamp

Destructive actions need explicit, current consent. Gated transitions can't auto-approve past a timeout. "Approved something similar yesterday" is not consent — by design, not by policy doc.

ART. 15 · ACCURACY & ROBUSTNESS

Look before the action

Consequence enrichment predicts affected resources before high-risk operations. Benchmarks carry corpus identity + commit_sha. The tamper-evident store catches silent drift.

ART. 50 · OUTPUT TRANSPARENCY

Machine-checkable provenance

C2PA Content Credentials attached to agent outputs via output_attest — "an AI made this" as a verifiable claim, not a footer nobody reads.

GDPR ART. 17 · ERASURE

The right to be forgotten, with receipts

memory_forget with a dry-run: see exactly what would be deleted, then delete it auditably. Erasure that proves itself happened.

Instinct

Engrams — memory that compiles

Retrieval answers questions. Engrams skip them. When the same lesson keeps getting re-learned from raw history, it's distilled into a named, versioned procedure that arrives before the agent acts — instinct, not search.

engram deploy-preflight @v3 intent "deploy to prod" distilled 14 sessions · 6 incidents (source-chunk hashes attached) requires tier ≥ trusted content 9-step preflight procedure status enabled · policy-hashed · verifiable

Distilled, not retrieved

Repeated patterns in your history compile into procedures with provenance — every engram carries hashes back to the source chunks it was learned from. You can always audit why the instinct exists.

Resolved by intent

At session start the agent declares what it's about to do; matching engrams arrive before the first action. No query needed — the pre-execution contract delivers the playbook up front.

Gated by tier

Each engram carries capability-class bounds — an agent only inherits procedures its passport tier allows. And it's local-first: a built-in catalog plus fact-backed overlays serve the same contract with zero cloud dependency.

Grounded in the real module — corecruxd/src/http/engrams.rs: versioned LocalEngram records with intent_bucket, query_pattern, capability_class_min/max, source_chunk_hashes and policy_hash; the local daemon serves a built-in catalog + __engram__::* fact overlays on the same contract as the hosted plane. Passports are introduced back in §9, so the tier-gating here already has its referent. The manifest figures ("14 sessions · 6 incidents") are illustrative.
