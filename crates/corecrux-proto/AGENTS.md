# corecrux-proto — agent notes

> Root `AGENTS.md` and `CLAUDE.md` still apply; this file adds crate-local context.

Protobuf/gRPC types for the CoreCrux data plane, auto-generated by `tonic-build`/`prost`
from the `.proto` sources in `proto/` at the repository root. The crate itself is two
`tonic::include_proto!` module declarations plus round-trip tests — there is no
hand-written logic to edit here.

## Key symbols
- `dataplane_v1` — append/read/replay/export RPCs (from `proto/corecrux_dataplane_v1.proto`);
  e.g. `AppendBatchRequest`, `AppendResult`, `FrameLocation`, `ReplaySessionRequest`
- `observe_v1` — observability/health RPCs (from `proto/corecrux_observe_v1.proto`)

## Test & verify
- `cargo test -p corecrux-proto` — wire round-trip tests (encode/decode, enum + oneof)
- Regeneration is automatic: `cargo build` runs `build.rs` (vendored protoc via
  `protoc_bin_vendored`); there is no separate codegen step to run or commit

## Local rules
- Never edit generated Rust — change the `.proto` files in `proto/` and rebuild.
- Proto changes must be backward-compatible: never reuse or renumber field tags, never
  change a field's type; deprecate + reserve instead. `corecruxd`, `corecruxctl`, and
  external dataplane clients all speak this wire format.
- Enum values and `oneof` variants follow the same rule — additive only.
- `proto/buf.yaml` / `buf.gen.yaml` exist for non-Rust consumers; keep them in sync with
  any proto changes.
